## What this is
A sibling of Sales Coach and Scorecard with the same Tide look: a DocuSign-style signing app for one document, the Company's non-disclosure agreement for office visitors (owner, 2026-10-28: "a simple one screen where you basically do a docu sign ... captures a receipt of your physical IP address every time you click the sections where you adopt and sign your name"). Release 1 (2026-10-29): the owner signs in with a password, makes a signing link (plus QR code and a Text it button), the visitor signs on their phone with no sign-in, and the record (every tap with server time, IP, Vercel location, device) plus the sealed PDF live in the owner's screens.

## Rules
- The owner approves scope before code. Build small, verified steps.
- Legal: `src/lib/nda-text.ts` is the agreement template, drafted and adversarially reviewed by a panel in the 2026-10-29 session (Michigan law, GLBA and health information, E-SIGN and Michigan UETA). It is not legal advice; the owner was told to have a Michigan attorney read it once. Change wording only with the owner's OK, bump `version` when you do, and never edit a frozen `envelopes.document` (what someone signed stays as it was).
- Evidence: every event is written by the server the moment it happens (`events`) with the IP from `x-real-ip` / first `x-forwarded-for` (Vercel sets them), the user agent, and Vercel's `x-vercel-ip-*` location. The browser reports only the kind of tap and, for adoption, the typed name, email and the two PNGs (checked: data URL, size, PNG signature, IHDR dimensions, `src/lib/png.ts`); it is never trusted for time or address. The database makes the record append-only: triggers in `0001_init.sql` refuse any update or delete on `events` and `signed_pdfs`, any change to an envelope's frozen fields (`document`, `token`, `issued_by`, `created_at`, `template_version`), any change to a completed or voided envelope beyond filling its two fingerprints once, and any delete (`scripts/check-db-guards.sh` proves it on the local database). Unique partial indexes make `consented`, `signed`, `completed` and `sealed` once per envelope and `initialed` once per section (`addEventOnce` returns the existing row on a duplicate). "Sign and finish" is one transaction (`complete_envelope`, called through `completeEnvelope`): the status flips once, from sent or opened, and the `signed` and `completed` events are written with the same instant as `completed_at`, so the tap's address and device are never lost. Then `sealEnvelope` (`src/lib/signing.ts`): SHA-256 of the canonical JSON (`canonicalAgreement`: the filled agreement including the consent and adoption statements, `completed_at` normalized to milliseconds and Z by `normalizeIso`, the envelope id, the signer's email, the template version), a deterministic PDF (`renderAgreementPdf`; same inputs, same bytes, `tests/pdf.test.ts`) stored in `signed_pdfs` (first store wins, `ignoreDuplicates`), the `sealed` event with both fingerprints, and a copy of them on the envelope. A failed seal is redone from the same record on the first download (`ensurePdf`), and gives the same bytes and hashes. Caps per link: 25 `opened` rows (later opens are not recorded), 5 adoptions, none after the first initial (`locked`), 50 `viewed_pdf` rows.
- Privacy: an envelope holds the signer's name, optional email, the signature and initials images, and the record. No other personal data. Logs carry ids and error classes only, never names, addresses or tokens.
- Secrets only in env vars. Never in chat, code, git or logs. Never put model identifiers in commits, PR text or code.
- Look: Tide (the same type, cards, radii and neutrals as Sales Coach and Scorecard) in Ink's own colorway in `src/app/globals.css`: graphite-to-slate gradient (`bg-tide`, `bg-tide-strong`) for the mark and primary buttons; gold tabs (`bg-tab`, `text-tab-text`, `border-tab-line`) wherever a signer taps; "paper" tokens (`bg-paper`, `text-paper-text`, `text-paper-muted`, `border-paper-line`) for the agreement sheet, which stays a light sheet in dark mode too (the ink of a signature image is black). Never hardcode a hex, `rgb()`, `white/` or `black/` color in a component (the QR code's two colors are the exception). Plus Jakarta Sans for text, Space Grotesk (`font-mono`) for hashes and times. Brand: `src/components/brand.tsx` (InkMark: a white fountain-pen nib on the gradient squircle; TkgMark; InkLockup "Ink by TKG"); `public/` icons, `og.jpg` and the iPhone opening screens come from `scripts/gen-icons.mjs` (`npm run icons`), same geometry; keep the two in sync.
- Signature styles: three open-license fonts in `public/fonts/` (Caveat, Dancing Script: OFL; Homemade Apple: Apache 2.0; licenses alongside). The signature and initials are PNGs drawn in the browser (`signature-pad.tsx`), so the PDF needs no font files and shows exactly what the signer saw. The PDF text uses the standard Helvetica (WinAnsi): `winAnsiSafe` folds smart punctuation and turns anything else into "?", so the template stays ASCII (tested).

## Stack (match the owner's other apps; do not substitute)
- Next.js 16.3.4 App Router (TypeScript strict, Tailwind 4, React 19), `src/proxy.ts` (not middleware; it skips `/s/` and `/api/`), async `params`/`searchParams`/`cookies()`. Read `node_modules/next/dist/docs/` before a new convention.
- Supabase Postgres (its own project) through `@supabase/supabase-js` with the service role key, server only (`src/lib/supabase.ts`). The browser never talks to Supabase. RLS on with no policies plus revoked grants for anon/authenticated (`supabase/migrations/0001_init.sql`).
- Sign-in: one password, `OWNER_PASSWORD`, checked in constant time (`src/lib/auth.ts`), HMAC-signed stateless cookie with a password tag (`src/lib/session.ts`; changing the password signs out every device), 180-day cookie, a per-address login throttle in `login_attempts` (10 wrong in 15 minutes; a 500-row flood cap only stops new rows, never a right password). `requirePage()` in the owner layout, `requireOwner()` in every action and owner route. Signing pages and `/api/sign/*` are gated by the link's token (`tokenLooksValid`, then a lookup of `envelopes.token`).
- Data (`src/lib/envelopes.ts`): `envelopes` (token, status sent/opened/completed/voided, the frozen `document`, the signer's name, email and PNGs, hashes, `expires_at` 14 days), `events` (append-only), `signed_pdfs`, `settings` (key `app`: company legal name, address, owner name, title, owner email), `login_attempts`. "Expired" is computed (`shownStatus`), not stored.
- Flow (`src/app/s/[token]/sign-view.tsx`, one screen): name + email + consent checkbox, "Create my signature" (records `consented`, opens the pad), adopt (records `adopted` and stores the PNGs), gold "Initial here" tabs on the seven `initial: true` sections (each records `initialed` once; a reload restores them from the events; the name and signature lock after the first initial), an unsigned copy to read or print (`GET /api/sign/<token>/draft`, no record), "Sign and finish" (`POST /api/sign/<token>/complete`: checks consent, signature and every initial, claims completion, records `signed` and `completed`, builds and stores the PDF, emails copies when `RESEND_API_KEY` + `EMAIL_FROM` are set). `opened` is recorded by the browser on mount so link-preview bots never count as an open; the owner's "Open it here" link carries `?h=1` so that open is labeled as a hand-over. The consent checkbox text and the adoption line are part of the frozen agreement (`NdaTemplate.consent`, `.adoption`), shown from `doc`, hashed with it and printed in the certificate. The effective date is the completion day in Detroit time; the screen says "the day you sign" and the complete call carries the date shown, refused with `date_changed` if midnight passed. The signed link keeps opening the PDF (`GET /api/sign/<token>/pdf`, which records `viewed_pdf`); the owner's copy is `GET /api/nda/<id>/pdf` and the record as JSON `GET /api/nda/<id>/record`.
- Forms that can fail (Settings, New NDA) submit through `onSubmit` + `new FormData` + `startTransition`, never a form `action` prop (React 19 resets a form after an action); the New NDA action redirects on success and the client rethrows the redirect. Client code that calls an action catches a throw (a lapsed session) and says "reload and sign in again".
- Links the app hands out come from `appBase()` (`APP_URL`, else the request's host). Timezone: America/Detroit everywhere (`src/lib/timezone.ts`); the PDF prints Eastern time and the exact UTC instant of every event.

## How to run and check
- `npm install`, `npm run dev`. Before every push: `npm run lint`, `npx tsc --noEmit` (`npx next typegen` first when routes change), `npm test`, `npm run build`.
- End to end: `scripts/local-db/start.sh --reset` (Postgres 16 + PostgREST stand-in, needs `/usr/lib/postgresql/16`), then build and start the app with the env in `.local-db/env` plus `OWNER_PASSWORD` and `APP_URL`, then `node scripts/smoke.mjs` (Playwright; screenshots and the signed PDF in `test-results/`), then `scripts/check-db-guards.sh` (the triggers). Run it on a fresh database.
- Env vars: see `SETUP.md` (no `.env.example`; `.env*` is gitignored).
